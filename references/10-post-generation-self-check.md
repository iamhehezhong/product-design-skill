# 生成后自检

在输出较完整的产品方案、页面结构、交互原型、HTML 原型或设计改版建议前，使用本文件做自检。目标是在交付给用户前，先发现明显问题并修正。

## 1. 自检问题

### 3 秒清晰度

- 目标用户能否在 3 秒内知道页面或流程是做什么的？
- 第一视觉焦点是否就是用户最需要的内容？
- 主操作是否明显，并且使用真实动作命名？

如果不满足：简化页面目标，重命名主按钮，把主任务移到视觉中心。

### 输入减少

- 设计是否减少了打字、配置、上传阻力、重复选择或手动整理？
- 是否合理使用默认值、模板、历史记录、上下文和自动识别？
- 是否只在当前阶段询问必要信息？

如果不满足：用示例、智能默认、建议动作和渐进披露替代空白输入。

### 视觉焦点

- 是否有太多模块、卡片、徽章、横幅或颜色互相竞争？
- 用户能否不读完所有内容，就看见状态和下一步？
- 次要功能、管理功能和运营内容是否与核心任务分层？

如果不满足：删除或收起次要模块，恢复清楚层级。

### 反馈与状态

- 每个重要动作是否都有反馈？
- 是否考虑空、加载、成功、失败、部分成功、权限不足和恢复状态？
- AI 是否说明它理解了什么、正在做什么？

如果不满足：补充状态设计，再交付流程。

### 掌控与恢复

- 用户能否编辑、撤销、取消、重试、恢复、跳过或人工接管？
- 高风险动作是否有确认或可逆机制？
- 失败后是否保留用户输入和已完成工作？

如果不满足：补上恢复机制，避免不可逆自动化。

### 选择架构

- 默认值是否透明且容易修改？
- 成本、风险和后果是否靠近决策点？
- 是否存在主要服务平台、却增加用户负担的摩擦？

如果不满足：明确说明推荐理由，删除不必要摩擦，让替代路径可见。

### 美学与人性

- 视觉气质是否符合产品类型？
- 是否尊重用户注意力、时间和情绪？
- 是否有只是为了炫技的视觉或交互？

如果不满足：减少装饰，让界面更安静、更清楚、更有用。

## 2. 必须修正规则

交付较完整设计前：

1. 用本文件快速检查设计。
2. 如果核心任务清晰度、输入负担、视觉扫描、反馈状态或掌控恢复低于 3 分，先修改设计。
3. 最终只呈现修正后的方案；除非用户要求，不展开内部迭代过程。

## 3. 简短自检输出

需要展示自检时使用：

```
自检：
- 3 秒清晰度：
- 输入减少：
- 视觉焦点：
- 反馈 / 恢复：
- 掌控感：
- 剩余风险：
```

## 4. 常见修正方式

- 主操作太多：只保留一个主操作，其余降级为次操作。
- 空白提示词：增加任务卡、模板、示例、上下文芯片和 AI 理解确认。
- 运营区域太大：移到任务下方、账户页或计费页。
- 后果不清楚：把时间、费用、风险和影响范围放到选择旁边。
- 配置太长：给推荐默认值，低频设置折叠为高级设置。
- AI 输出不清楚：增加摘要、可信度、来源、可编辑结果和下一步动作。
- 移动端混乱：一屏一个任务、一个主操作、一个导航层。
