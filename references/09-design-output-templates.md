## 9. HTML 原型说明

当需要输出 HTML 原型时使用。

```
原型目标：
目标视口：
核心交互：
必须展示的状态：
示例数据：
设计气质：
需要的素材：

实现约束：
- 使用语义化结构。
- 每个视图只突出一个主任务。
- 避免无意义装饰。
- 响应式尺寸稳定。
- 需要时包含空、加载、错误、成功状态。

验收标准：
- 用户能在原型中完成核心任务。
- 主操作无需解释即可看见。
- 文案不溢出。
- 移动端和桌面端布局都清楚。
```

## 10. 产品设计资料采集表

适用于开始设计前向用户收集信息。

```text
1. 产品是什么？
2. 目标用户是谁？
3. 用户最核心的任务是什么？
4. 当前流程或想法是什么？
5. 用户最费脑、费手、费眼的地方是什么？
6. 有没有截图、原型、竞品、文档？
7. 设计要更偏效率、信任、温暖、专业、年轻，还是探索感？
8. 必须遵守哪些业务、技术、合规约束？
9. 哪些状态必须覆盖？
10. 最终输出是什么：方案、页面结构、交互流程、评审意见、原型文案？
```

## 14. 优秀设计交付要求

输出优秀设计作品时，至少满足：

- 能说清目标用户和核心任务。
- 能画出主路径，而不是只列功能。
- 能说明每个页面第一眼应该看到什么。
- 能说明用户输入从哪里被减少。
- 能说明关键状态和异常恢复。
- 能说明视觉层级如何帮助少用眼。
- 能说明 AI 或推荐如何保持用户掌控。
- 能给出可执行的组件、文案或原型。
