# 产品设计输入清单

本文件用于收集产品设计前的全部输入。目标是让设计输出有依据，而不是凭空生成“看似合理”的页面。

## 1. 项目背景

需要收集：

- 产品名称
- 产品类型：工具、内容、电商、SaaS、AI、硬件、服务、社区等
- 所处行业
- 当前阶段：0 到 1、改版、增长、留存、效率优化、商业化、B 端交付等
- 业务目标
- 用户目标
- 当前最主要问题
- 成功标准

关键问题：

- 这个产品为什么现在需要设计？
- 是要提升转化、降低流失、提升效率、降低支持成本，还是创造新体验？
- 什么指标能证明设计有效？

## 2. 目标用户

需要收集：

- 用户角色
- 新手/熟手比例
- 使用频率
- 专业程度
- 年龄、设备、环境、注意力状态
- 用户已有习惯
- 用户最怕什么
- 用户最烦什么
- 用户最想省什么

关键问题：

- 用户是否愿意学习？
- 用户是在安静环境，还是碎片化场景？
- 用户是主动使用，还是被迫完成任务？
- 用户更需要效率、信任、表达、掌控，还是陪伴？

## 3. 核心任务

需要收集：

- 用户要完成的主要任务
- 任务触发条件
- 任务开始前用户知道什么
- 任务中用户要做哪些判断
- 任务完成的标准
- 完成后用户期待什么

任务拆解模板：

```text
任务名称：
用户动机：
起点：
终点：
必要步骤：
可省略步骤：
可自动化步骤：
高风险步骤：
用户最容易卡住的位置：
```

## 4. 当前流程

需要收集：

- 当前用户路径
- 页面截图或原型
- 关键点击路径
- 表单字段
- 决策节点
- 等待环节
- 错误环节
- 人工介入环节

关键问题：

- 当前流程需要几步？
- 哪一步最耗时？
- 哪一步最让用户不确定？
- 是否存在重复输入或重复确认？
- 是否有无意义跳转？

## 5. 内容与信息结构

需要收集：

- 页面上的全部信息
- 信息优先级
- 用户最关心的信息
- 用户需要比较的信息
- 用户需要搜索或筛选的信息
- 信息之间的层级关系
- 术语和标签

关键问题：

- 哪些信息必须首屏可见？
- 哪些信息可以延后、折叠、悬浮、详情页展示？
- 哪些信息是系统内部语言？
- 用户是否需要跨页面记忆信息？

## 6. 操作与输入

需要收集：

- 用户必须填写的字段
- 可选字段
- 可自动识别字段
- 可默认字段
- 可从历史记录带出的字段
- 可由 AI 生成的字段
- 可批量处理的操作

关键问题：

- 哪些输入真的必要？
- 哪些输入可以从上下文推断？
- 哪些选择可以给推荐值？
- 是否可以先产出草稿，再让用户编辑？

## 7. 状态与异常

需要收集：

- 默认状态
- 加载状态
- 空状态
- 成功状态
- 失败状态
- 部分成功状态
- 权限不足
- 网络异常
- 数据过期
- 冲突状态
- AI 不确定状态

关键问题：

- 用户是否知道系统正在做什么？
- 出错后是否知道如何恢复？
- 是否有撤销、重试、保存草稿？
- AI 输出不可靠时如何提示？

## 8. 平台与设备

需要收集：

- Web、iOS、Android、桌面、小程序、企业微信、钉钉等
- 屏幕尺寸
- 输入方式：鼠标、触摸、键盘、语音、扫码、拍照
- 网络环境
- 是否需要离线
- 是否需要跨端同步

关键问题：

- 高频操作是否符合设备特性？
- 移动端是否避免复杂表格和密集操作？
- 桌面端是否支持效率操作？

## 9. 品牌与美学

需要收集：

- 品牌关键词
- 希望给用户的第一印象
- 行业气质
- 竞品视觉风格
- 禁用风格
- 颜色、字体、图标、插画规范

关键问题：

- 产品应该显得专业、温暖、轻盈、可信、年轻，还是高效？
- 视觉是否帮助用户理解主次？
- 是否存在过度装饰？

## 10. 竞品与案例

需要收集：

- 直接竞品
- 间接竞品
- 用户熟悉的通用产品
- 值得借鉴的跨行业案例
- 失败案例

案例记录：

```text
产品：
场景：
截图/链接：
用户任务：
亮点：
减少了什么成本：
可能的问题：
可迁移启发：
```

## 11. 业务与技术约束

需要收集：

- 技术可行性
- 数据来源
- 权限规则
- 合规要求
- 运营需求
- 商业目标
- 时间、人力、开发成本

关键问题：

- 哪些设计是当前版本必须做？
- 哪些可以作为后续增强？
- 哪些约束不能牺牲用户理解？

## 12. 验证方式

需要收集：

- 可用性测试问题
- A/B 测试指标
- 行为数据
- 用户访谈问题
- 客服/销售反馈
- 上线后监控指标

关键问题：

- 如何证明设计让用户少用脑？
- 如何证明设计让用户少用手？
- 如何证明设计让用户少用眼？
