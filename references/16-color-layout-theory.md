# 色彩、色系、布局与设计系统理论

本文件用于补充产品布局、配色、色系、视觉层级、设计 Token、可访问性和设计系统选型。使用时必须服从 `01-basic-principles.md` 的最高原则：少用脑、少用手、少用眼，并将理论转译成具体设计决策。

## 使用场景

在以下任务中读取本文件：

- 设计或评审页面布局、信息区块、工作台首页、后台系统、移动 App、数据看板。
- 选择主色、辅助色、中性色、语义色、图表色或品牌色。
- 判断界面是否杂乱、是否缺少重点、是否颜色过多、是否对比度不足。
- 建立设计系统、主题系统、设计 Token、浅色/深色模式或多端适配规则。
- 检查视觉稿、截图、HTML、CSS 是否具备一致的布局、色彩和状态表达。

## 总体判断原则

布局和颜色不是装饰，而是帮助用户更快理解、判断和行动的结构化语言。

- 少用脑：颜色含义稳定，布局结构符合用户预期，不让用户猜哪里重要、哪里可点、哪里危险。
- 少用手：关键操作放在顺手位置，默认状态合理，减少跳转、滚动、筛选和重复定位。
- 少用眼：通过空间、对比、字号、色彩和留白建立清晰视觉层级，让用户一眼看到主任务。
- 有掌控：状态、反馈、选中、禁用、错误、警告、成功都能被清楚识别，不能只靠颜色表达。
- 有美感：色彩克制、比例协调、细节统一，品牌感服务任务而不是压过任务。

## 色彩基础理论

### 色相、饱和度、明度

- 色相用于区分类型或表达品牌气质，但不应承担过多含义。
- 饱和度影响情绪和注意力。高饱和色适合强调，不适合大面积铺底。
- 明度决定可读性和层级。文字、图标、边框、背景必须先满足清晰，再考虑风格。
- 对复杂业务系统，优先用明度和空间建立层级，再用少量品牌色强调关键动作。

### 色彩比例

可使用 `60/30/10` 作为经验比例，但不要机械套用：

- 60%：背景、页面底色、大面积中性色，保持安静。
- 30%：内容区块、容器、浅色辅助层，建立区域关系。
- 10%：品牌色、关键按钮、状态、重点信息，引导用户行动。

如果一个页面到处都是强调色，等于没有强调色。企业系统尤其要克制，颜色首先服务信息传达、操作引导和交互反馈。

### 冷暖与情绪

- 蓝色、青色常用于科技、效率、信任、工具型产品，但容易变得冷淡，需要用排版、微文案和状态反馈补足人性。
- 绿色适合成功、健康、通过、增长，但在不同文化和金融场景中含义可能变化。
- 红色适合错误、危险、删除、异常，也可能在中文金融语境中表示上涨，必须结合行业认知。
- 黄色、橙色适合提醒、等待、轻度风险，不适合表示严重错误。
- 紫色、渐变色可用于创意、AI、品牌表达，但不应成为后台系统或效率工具的主导视觉。

## 色系结构

### 主色

主色用于表达品牌和关键行动。主色必须回答：

- 它代表什么品牌气质或产品心智？
- 它在哪些地方出现：主按钮、链接、选中、焦点、重点数据？
- 它在哪些地方不能出现：普通文本、装饰背景、低优先级按钮、危险操作？
- 它在浅色、深色、高对比模式下是否仍然可读？

### 辅助色

辅助色用于扩展品牌气质或区分类别。使用规则：

- 辅助色数量要少，通常 1-3 个足够。
- 辅助色不能和语义色冲突，例如不要把红色作为普通品牌装饰后又用红色表示删除。
- 辅助色应用于插图、标签、分类、轻量强调，不应抢走主操作的注意力。

### 中性色

中性色是界面清晰度的骨架，常用于背景、文字、边框、分割线和禁用态。

- 文本至少分为主文本、次级文本、弱提示、禁用文本。
- 背景至少分为页面背景、容器背景、悬浮/弹层背景、选中背景。
- 边框和分割线应足够弱，帮助分组但不制造噪音。
- 企业系统可用多级灰阶支撑密集信息，但必须避免整页灰糊、主次不明。

### 语义色

语义色用于传达状态和反馈，应全产品一致。

- 成功：完成、通过、启用、已同步。
- 警告：待处理、风险、即将超时、需要关注。
- 错误：失败、阻断、删除、异常、不可恢复风险。
- 信息：提示、说明、一般通知、系统反馈。
- 禁用：不可操作、权限不足、条件未满足。

语义色不能只靠颜色表达，必须配合文字、图标、形状或位置。色盲用户、低亮度环境和投影场景下，单靠颜色会失效。

## 布局理论

### 信息架构优先

布局先解决“用户来这里做什么”，再解决“界面怎么排”。

- 每个页面只能有一个主任务，其他内容围绕主任务组织。
- 重要信息放在首屏和视线动线的关键位置。
- 次要信息折叠、分组、延后或放入详情，不要与主任务平级竞争。
- 如果首页像功能清单而不是任务入口，通常会增加认知负担。

### 视觉层级

视觉层级由以下因素共同建立：

- 空间：位置、留白、分组、距离。
- 尺寸：标题、数字、按钮、卡片大小。
- 对比：明暗、粗细、色彩、背景。
- 顺序：从上到下、从左到右、从概览到详情。
- 状态：选中、悬停、禁用、加载、错误。

不要只依赖颜色建立层级。优先用结构、字号、间距和内容密度让重点自然浮现。

### 网格与间距

- 使用稳定的间距系统，如 4/8pt 或 4/8px 倍数。
- 同类元素使用一致间距，不同层级用明显差异。
- 容器内边距、组件间距、区块间距应形成清晰节奏。
- 内容密集的后台系统可以更紧凑，但不能牺牲可读性和点击准确性。
- 移动端要尊重安全区、手指触达和拇指热区，避免关键操作贴边或过小。

### 常见布局模式

- 单列任务流：适合表单、创建、编辑、引导、移动端核心流程。
- 主从布局：适合列表-详情、消息、客户、工单、文档管理。
- 仪表盘布局：适合监控和概览，但要避免堆满指标，应突出异常、趋势和下一步行动。
- 工作台布局：适合高频任务入口、待办、最近使用、核心数据和快捷动作。
- 支撑面板：适合在主任务旁提供上下文、历史、预览、AI 建议或辅助信息。
- 分步布局：适合复杂配置，但每一步都应有明确目标、默认值和可恢复路径。

## 设计系统与 Token

设计系统要把视觉决策从“凭感觉”变成“可复用的规则”。

### Token 分层

推荐使用三层 Token：

- 原始 Token：基础颜色、字号、圆角、阴影、间距，例如 `blue-600`、`gray-100`。
- 语义 Token：表达用途，例如 `color-text-primary`、`color-bg-page`、`color-border-default`。
- 组件 Token：绑定组件状态，例如 `button-primary-bg`、`input-border-error`、`tag-warning-bg`。

设计和开发交付时，优先使用语义 Token 和组件 Token。不要在业务页面随意写死颜色值，否则很难维护深色模式、品牌换肤和一致性。

### 多模式

同一套 Token 应考虑不同上下文：

- 浅色模式。
- 深色模式。
- 高对比模式。
- 移动端/桌面端密度。
- 品牌主题或租户主题。
- 国际化语言导致的文本长度变化。

多模式不是换一组颜色这么简单，要验证文字、图标、边框、阴影、禁用态和图表是否仍然清晰。

## 可访问性与对比度

### 对比度底线

以 WCAG 2.2 AA 为常用底线：

- 普通文本和背景对比度至少 `4.5:1`。
- 大号文本至少 `3:1`。
- 图标、边框、输入框、焦点框、状态指示等非文本关键元素至少 `3:1`。

如果产品用于户外、投影、低亮度设备、老年用户或长时间办公，建议比最低标准更高。

### 不只靠颜色

以下信息不能只用颜色表达：

- 错误和成功。
- 必填与选填。
- 当前选中项。
- 图表系列。
- 股票/销售/业务趋势。
- 风险等级。
- 链接和可点击状态。

必须同时使用文字、图标、形状、线型、位置、粗细或辅助说明。

## 企业系统配色规则

企业系统的优秀配色通常是克制、稳定、可扫描的。

- 页面大面积使用中性色，主色只用于关键路径和当前定位。
- 功能色保持语义稳定，不因品牌风格随意变化。
- 不要让图表色、标签色、状态色、品牌色互相抢夺注意力。
- 导航、筛选、表格、表单、详情、弹窗要共享同一套颜色语义。
- 状态优先级要明确：错误高于警告，警告高于信息，信息高于普通提示。
- 高风险操作不能只靠红色按钮，应有清晰文案、二次确认和可恢复策略。

## 移动 App 配色规则

移动端屏幕小、环境变化大，颜色和布局要更轻。

- 优先使用平台系统色和语义色，使 App 感觉属于该平台。
- 品牌色用于关键动作、选中态和少量品牌识别，不要铺满导航和控件。
- 工具栏、底部栏、浮层应保持清晰，避免彩色内容与控件重叠导致不可读。
- 支持浅色/深色模式，并检查图片、图标、阴影和半透明材质下的可读性。
- 重要操作要在拇指可达区域，但危险操作避免误触。
- 小屏中不要同时出现多个同等强度的 CTA。

## 数据可视化配色规则

图表配色优先服务准确理解。

- 分类色用于区分对象，连续色用于大小变化，发散色用于正负或偏离基准。
- 图表颜色数量有限，超过 6-8 类时应改用分组、筛选、排序或交互高亮。
- 同一指标在不同图表中使用同一颜色，避免用户重新学习。
- 红绿配色必须结合文化和色盲可识别性，必要时改用蓝橙、形状或线型。
- 异常、预警、超标用语义色突出，但不要让所有图表都“报警化”。
- 图例靠近图形，最好直接标注关键数据，减少来回扫视。

## 设计库参考

### Material Design 3

适合跨平台产品、Android 生态、多端响应式系统。可参考：

- 动态色彩、主色/辅助色/第三色、表面色、语义角色。
- 适配断点、feed、list-detail、supporting pane 等典型布局。
- 组件状态和可访问性规则。

### Apple Human Interface Guidelines

适合 iOS、iPadOS、macOS、watchOS、visionOS 体验。可参考：

- 系统色、动态色、浅色/深色/高对比适配。
- 安全区、平台布局、Dynamic Type、国际化文本长度。
- 品牌色克制使用，优先放在关键动作、选中态和内容层。
- 简洁、熟悉、掌控、人性与细节工艺。

### Ant Design

适合企业级 Web、中后台、B2B 系统。可参考：

- 系统级色板、产品级色彩体系、品牌色、功能色、中性色。
- 企业产品中颜色服务信息传达、操作引导和反馈，不破坏效率。
- 表格、表单、筛选、导航、数据展示等常见后台模式。

### Microsoft Fluent

适合生产力工具、企业协作、多产品矩阵。可参考：

- 中性色、共享色、品牌色的职责分离。
- 语义色用于重要信息，不用于装饰。
- 品牌色避免大面积滥用，以免削弱层级。
- 交互状态从默认、悬停、按下到选中要有连续变化。

### IBM Design Language / Carbon

适合复杂企业产品、数据密集系统、专业工具。可参考：

- 多级灰阶和核心品牌色支撑专业、克制的界面。
- 颜色家族和色阶用于构建稳定系统，而不是单页临时配色。
- 复杂产品中要用设计系统保证一致性、可访问性和工程可落地。

## 检查清单

评审布局和颜色时，至少检查：

- 页面主任务是否一眼可见？
- 首屏是否有明确的信息优先级，而不是平均铺开？
- 关键操作是否在用户完成任务的自然位置？
- 主色、辅助色、语义色、中性色是否职责清楚？
- 同一颜色是否被用于多个互相冲突的含义？
- 是否存在颜色太多、饱和度太高、整页过艳或过灰的问题？
- 文本、图标、边框、焦点、禁用态是否满足对比度要求？
- 错误、警告、成功、选中是否不只依赖颜色表达？
- 图表色是否支持快速比较，而不是让用户反复看图例？
- 布局、间距、圆角、阴影、边框是否形成统一节奏？
- 深色模式、移动端、宽屏、国际化长文案是否仍可用？
- CSS 或视觉稿是否使用设计 Token，而不是页面级硬编码颜色？

## 常见问题与改进方向

- 问题：品牌色铺满导航、按钮、卡片和背景。  
  改进：保留品牌色用于主 CTA、选中态和重点信息，大面积区域改用中性色。

- 问题：多个卡片同等突出，首页没有重点。  
  改进：按用户任务重排，把待办、异常、最近使用和主操作放到首屏核心位置。

- 问题：红色既表示品牌，又表示错误。  
  改进：重新定义品牌色或错误色，确保语义稳定。

- 问题：灰色文字过浅，表格密集但难读。  
  改进：提高正文和次级文字对比度，用分组、固定列、悬停态和行高优化扫描。

- 问题：图表色过多，用户无法记住每种颜色含义。  
  改进：减少默认系列，突出关键项，提供筛选、高亮、排序和直接标注。

- 问题：深色模式只是反转颜色。  
  改进：重新校准背景、容器、边框、文字、阴影、语义色和图表色的明度关系。

## 与评分体系的关系

本文件不新增评分维度，也不改变 `08-design-scoring-system.md` 的权重。发现的问题应映射到现有维度：

- 认知负担：颜色含义混乱、层级不清、布局不符合任务预期。
- 操作效率：关键操作位置不顺手、需要过多跳转或筛选。
- 视觉扫描：重点不突出、颜色噪音过多、对比度不足、信息密度失控。
- 掌控感：状态反馈不清、错误/禁用/选中不可识别。
- 美学与一致性：色系不成体系、间距和组件不统一、品牌色滥用。
- 可访问性与人性：仅靠颜色表达、深色模式不可读、长时间使用疲劳。
